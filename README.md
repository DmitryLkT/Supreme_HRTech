# Altra — платформа адаптации сотрудников

Altra — веб-приложение на Django для адаптации сотрудников: обучение, отслеживание прогресса, маршрут 30/60/90, вопросы наставнику и регулярные анкеты самочувствия

## Возможности

### Для сотрудника

- Вход и выход из системы.
- Просмотр опубликованных учебных модулей.
- Открытие учебного материала и вопросов модуля.
- Выбор варианта ответа и получение результата проверки.
- Сохранение ответов на учебные вопросы.
- Отметка модуля как завершённого.
- Просмотр количества завершённых модулей и процента прохождения.
- Определение следующего незавершённого модуля.
- Сохранение личного прогресса между сеансами.
- Просмотр маршрута адаптации 30/60/90.
- Изменение статуса выполнения шагов маршрута.
- Отправка вопросов наставнику и просмотр ответов.
- Заполнение опубликованных анкет самочувствия.
- Ограничение повторного заполнения одной анкеты в течение недели.

### Для HR

- Просмотр дашборда с прогрессом сотрудников.
- Поиск сотрудников по логину, имени и фамилии.
- Просмотр подробной статистики конкретного сотрудника.
- Просмотр сохранённых ответов на учебные вопросы.
- Просмотр маршрутов адаптации.
- Просмотр вопросов наставнику и отправка ответов.
- Формирование отчёта по анкетам самочувствия.
- Выбор периода для отчёта.
- Просмотр показателей участия и результатов ответов.

### Для администратора

- Управление пользователями, отделами и группами.
- Создание и редактирование учебных модулей.
- Управление порядком и публикацией модулей.
- Создание вопросов и вариантов ответов.
- Просмотр сохранённого прогресса и учебных ответов.
- Управление шагами маршрута адаптации.
- Управление анкетами и их версиями.
- Настройка ролей через management-команду.

### Сервисный слой

Часть бизнес-логики вынесена из представлений в сервисы.

В `onboarding/services/` находятся операции с учебными модулями, вопросами, прогрессом сотрудников и статистикой дашборда.

В `health/services/` находятся:

- синхронизация определений анкет с базой;
- управление публикацией;
- создание отправок и проверка ответов;
- определение недельных периодов;
- подготовка данных отчётов.

Представления обрабатывают HTTP-запросы, вызывают сервисы и передают данные в шаблоны.

## Модели данных

### Приложение `users`

| Модель | Назначение |
|---|---|
| `Department` | Отдел сотрудника с уникальным названием |
| `User` | Пользователь на основе `AbstractUser`, связанный с отделом |

В настройках используется пользовательская модель:

```python
AUTH_USER_MODEL = "users.User"
```

Отдел пользователя — обязательная связь. Удаление отдела, на который ссылаются пользователи, защищено через `PROTECT`.

### Приложение `onboarding`

| Модель | Назначение |
|---|---|
| `Module` | Учебный модуль, порядок показа и признак публикации |
| `ModuleCompletion` | Факт завершения модуля конкретным пользователем |
| `Question` | Учебный вопрос внутри модуля |
| `AnswerOption` | Вариант ответа с признаком правильности |
| `AnswerSubmission` | Сохранённый ответ пользователя на учебный вопрос |

### Приложение `journey`

| Модель | Назначение |
|---|---|
| `PathStep` | Шаг маршрута адаптации |
| `PathProgress` | Выполнение шага конкретным сотрудником |
| `MentorQuestion` | Вопрос сотрудника наставнику и ответ на него |

### Приложение `health`

| Модель | Назначение |
|---|---|
| `Questionnaire` | Анкета и её статус публикации |
| `QuestionnaireVersion` | Версия анкеты с определением вопросов |
| `Submission` | Заполнение анкеты сотрудником за определённую неделю |
| `Answer` | Ответ на отдельный вопрос анкеты |

### Расчёт прогресса

При расчёте учитываются опубликованные модули и завершения опубликованных модулей.

```python
round(completed_count / total_modules * 100) if total_modules else 0
```

Если опубликованных модулей нет, прогресс равен `0`.

Следующий модуль определяется среди опубликованных и ещё не завершённых модулей с учётом порядка модулей.

## Локальный запуск

Команды ниже рассчитаны на Windows PowerShell. Python должен быть установлен, а терминал — открыт в папке проекта с `manage.py`.

### 1. Создать виртуальное окружение

Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 2. Установить зависимости

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 3. Настроить переменные окружения

Создайте `.env` рядом с `manage.py`.

Пример для локальной разработки:

```env
SECRET_KEY=replace-with-your-local-secret-key
DEBUG=True
ALLOWED_HOSTS=127.0.0.1,localhost
```

Основные переменные:

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | Обязательный секретный ключ Django |
| `DEBUG` | Режим отладки; включается значением `True` |
| `ALLOWED_HOSTS` | Разрешённые хосты через запятую |
| `DATABASE_URL` | Строка подключения к базе данных |
| `RENDER_EXTERNAL_HOSTNAME` | Дополнительный разрешённый хост на Render |

Если `DATABASE_URL` не задана и `DEBUG=True`, используется SQLite:

```text
db.sqlite3
```

Если `DATABASE_URL` задана, подключение настраивается по этой переменной.

При `DEBUG=False` отсутствие `DATABASE_URL` вызывает ошибку конфигурации.

### 4. Применить миграции

```bash
python manage.py migrate
```

### 5. Создать отдел

Пользовательская модель требует отдел, поэтому перед созданием администратора нужно создать хотя бы один отдел:

```bash
python manage.py shell
```

В открывшейся оболочке:

```python
from users.models import Department

department, created = Department.objects.get_or_create(
    name="Администрация",
)
print(department.pk)
exit()
```

Сохраните выведенный идентификатор отдела.

### 6. Создать администратора

```bash
python manage.py createsuperuser
```

Введите логин, пароль и идентификатор существующего отдела при запросе поля `department`.

### 7. Подготовить роли и данные

Создать группы и настроить права:

```bash
python manage.py setup_roles
```

Заполнить базовые шаги маршрута:

```bash
python manage.py seed_path_steps
```

Синхронизировать каталог анкет:

```bash
python manage.py sync_questionnaires
```

При первой синхронизации пустого каталога анкета `wellbeing` публикуется автоматически. Повторная синхронизация сохраняет существующий статус публикации.

При необходимости загрузить учебный контент:

```bash
python manage.py loaddata fixtures/learning_content.json
```

### 8. Запустить сервер

```bash
python manage.py runserver
```

Адрес сервера:

```text
http://127.0.0.1:8000/
```
### PostgreSQL

Для подключения PostgreSQL задайте `DATABASE_URL`:

```env
DATABASE_URL=postgresql://hrtech_user:password@localhost:5432/hrtech
```

При `DEBUG=False` настройки подключения включают требование SSL. База данных должна поддерживать такое подключение.

### Серверная сборка

Скрипт `build.sh` устанавливает зависимости и собирает статические файлы:

```bash
bash build.sh
```

Миграции выполняются отдельно:

```bash
python manage.py migrate
```

Пример запуска через Gunicorn:

```bash
gunicorn config.wsgi:application
```

## Работа с приложением

### Роли и выборка сотрудников

В исходную выборку сотрудников входят пользователи, у которых:

- `is_active=True`;
- `is_superuser=False`;
- `is_staff=False`;
- нет членства в группе `HR`.

Права доступа к HR-разделам проверяются отдельно.

### Поиск сотрудников

Поиск выполняется по полям:

- `username`;
- `first_name`;
- `last_name`.

Для каждого слова используется `icontains`: поиск по части значения без учёта регистра в пределах возможностей используемой базы данных.

Если запрос содержит несколько слов, сотрудник должен соответствовать каждому слову. При этом разные слова могут совпадать с разными полями.

Например, запрос:

```text
ivan petrov
```

может найти сотрудника с именем `Ivan` и фамилией `Petrov`.

Пустая строка или строка из пробелов сохраняет переданную выборку без дополнительной фильтрации.

### Основные маршруты

| Раздел | URL | Назначение |
|---|---|---|
| Вход | `/login/` | Аутентификация |
| Выход | `/logout/` | Завершение сеанса |
| Корневой адрес | `/` | В текущем порядке маршрутов открывает актуальную опубликованную анкету |
| Учебный модуль | `/modules/<module_id>/` | Материал и вопросы модуля |
| Завершение модуля | `/modules/<module_id>/complete/` | Отметка о прохождении |
| Ответ на вопрос | `/questions/<question_id>/answer/` | Проверка учебного ответа |
| Маршрут адаптации | `/path/` | Шаги маршрута 30/60/90 |
| Статус шага | `/path/steps/<step_id>/toggle/` | Изменение выполнения шага |
| Наставник | `/mentor/` | Вопросы сотрудника |
| HR-дашборд | `/hr/` | Прогресс сотрудников |
| Карточка сотрудника | `/hr/employees/<user_id>/` | Подробная статистика |
| Учебные ответы | `/hr/answers/` | Сохранённые ответы на учебные вопросы |
| Маршруты для HR | `/hr/path/` | Просмотр маршрутов сотрудников |
| Наставничество для HR | `/hr/mentor/` | Вопросы сотрудников |
| Ответ наставника | `/hr/mentor/<question_id>/answer/` | Ответ на вопрос сотрудника |
| Версия анкеты | `/health/questionnaires/versions/<version_id>/` | Заполнение анкеты |
| Отчёт по анкетам | `/hr/report/` | Отчёт за выбранный период |
| Администрирование | `/admin/` | Управление данными |

### Сценарий обучения

1. Сотрудник входит в систему.
2. Открывает опубликованный модуль.
3. Изучает материал и отвечает на вопросы.
4. Получает результат проверки ответа.
5. Отмечает модуль как завершённый.
6. Продолжает обучение с сохранённым прогрессом.

### Сценарий маршрута и наставничества

1. Сотрудник открывает `/path/`.
2. Просматривает шаги адаптации.
3. Меняет статус выполнения шагов.
4. При необходимости открывает `/mentor/` и отправляет вопрос.
5. После ответа наставника просматривает его в разделе вопросов.

### Сценарий заполнения анкеты

1. Сотрудник открывает опубликованную анкету.
2. Выбирает ответы на вопросы.
3. Отправляет анкету.
4. Система проверяет ответы и сохраняет результат.
5. При повторном открытии в ту же неделю показывает состояние завершённого заполнения.

Ограничение повторной отправки действует для сотрудника и анкеты в рамках недели, а не только для отдельной версии анкеты.

### Сценарий HR

1. HR входит в систему.
2. Открывает `/hr/` и находит сотрудника.
3. Проверяет прогресс и подробную статистику.
4. При необходимости просматривает учебные ответы.
5. Открывает маршруты адаптации или вопросы наставнику.
6. В `/hr/report/` выбирает период и формирует отчёт по анкетам.

## Ограничения и особенности

- Пользователь должен быть связан с существующим отделом.
- Исходная выборка сотрудников исключает неактивных пользователей, staff, суперпользователей и участников группы `HR`.
- В расчёте учебного прогресса учитываются опубликованные модули.
- Завершение модуля и ответы на вопросы представлены отдельными сущностями.
- На корневом адресе `/` сейчас приоритет имеет приложение `health`.
- Для работы корневой страницы нужна опубликованная анкета.
- SQLite имеет особенности поиска без учёта регистра для символов вне ASCII; проверки поиска на кириллице нужно учитывать отдельно.
- Очистка просроченных отправок запускается отдельной командой.
- Для серверного размещения необходимо настроить разрешённые хосты и параметры безопасности Django под выбранную инфраструктуру.
