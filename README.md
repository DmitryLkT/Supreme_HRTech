## Возможности

### Для сотрудника

- Вход и выход из системы.
- Просмотр опубликованных модулей адаптации.
- Открытие отдельной страницы с учебным материалом.
- Отметка модуля как завершённого.
- Просмотр статуса каждой карточки и общего процента завершения.
- Сохранение личного прогресса после выхода и повторного входа.

### Для HR

- Вход и выход из системы.
- Просмотр успеваемости сотрудников.
- Открытие отдельной страницы с подробным описанием успеха сотрудника.

### Для администратора

- Создание пользователей через Django Admin.
- Создание и редактирование модулей.
- Настройка порядка отображения материалов.
- Публикация и скрытие модулей.

## Модели данных

### Module — учебный модуль

| Поле | Содержание |
|---|---|
| `id` | Автоматический первичный ключ |
| `title` | Название, до 200 символов |
| `description` | Краткое описание |
| `content` | Учебный текст; может быть пустым |
| `order` | Порядок отображения |
| `is_published` | Признак публикации; по умолчанию `False` |

Модули по умолчанию сортируются по `order`, затем по `id`. В каталоге и на странице материала доступны только опубликованные записи.

### ModuleCompletion — завершение модуля

| Поле | Содержание |
|---|---|
| `id` | Автоматический первичный ключ |
| `user` | Ссылка на модель пользователя из `AUTH_USER_MODEL` |
| `module` | Ссылка на учебный модуль |
| `completed_at` | Дата и время создания записи |

### Question — вопрос из модуля

| Поле | Содержание |
|---|---|
| `id` | Автоматический первичный ключ |
| `module` | Ссылка на учебный модуль |
| `text` | Текст вопроса |
| `order` | Порядок отображения |

### AnswerOption — варианты ответа на вопрос

| Поле | Содержание |
|---|---|
| `id` | Автоматический первичный ключ |
| `question` | Ссылка на вопрос |
| `text` | Текст ответа |
| `is_correct` | Правильный ли ответ |

### Расчёт прогресса

```text
Прогресс = завершённые опубликованные модули текущего пользователя
           / все опубликованные модули × 100%
```

Результат округляется до целого процента. Если опубликованных модулей нет, отображается 0%.

## Локальный запуск

Команды ниже рассчитаны на Windows PowerShell. Python должен быть установлен, а терминал — открыт в папке проекта с `manage.py`.

### 1. Создать виртуальное окружение

Если `.venv` ещё нет:

```powershell
py -3.14 -m venv .venv
```

### 2. Установить Django

Можно использовать интерпретатор окружения напрямую — активация не обязательна:

```powershell
.\.venv\Scripts\python.exe -m pip install "Django==5.2.17"
```

Это версия, с которой разрабатывался текущий прототип. Для дальнейшей поддержки зависимости следует обновлять осознанно, с запуском тестов.

### 3. Применить миграции

```powershell
.\.venv\Scripts\python.exe manage.py migrate
```

Если база ещё не существует, Django создаст её. При развёртывании существующего проекта `makemigrations` обычно не требуется: готовые миграции должны храниться вместе с исходным кодом.

### 4. Создать администратора

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Указать имя пользователя, при необходимости email и пароль. При вводе пароля символы в терминале не отображаются.

### 5. Запустить сервер разработки

```powershell
.\.venv\Scripts\python.exe manage.py runserver
```

Адреса:

- Главная: http://127.0.0.1:8000/
- Вход: http://127.0.0.1:8000/login/
- Административная панель: http://127.0.0.1:8000/admin/


## Работа с приложением

### Сценарий сотрудника

1. Открыть главную страницу.
2. Войти по логину и паролю.
3. Открыть материал из карточки.
4. Прочитать текст и нажать «Завершить модуль».
5. Вернуться на главную и проверить статус и процент.
6. Выйти и снова войти — сохранённый прогресс остается.

### Основные маршруты

| Адрес | Метод | Назначение |
|---|---|---|
| `/` | GET | Каталог и личный прогресс |
| `/login/` | GET / POST | Форма входа и отправка учётных данных |
| `/logout/` | POST | Выход из системы |
| `/admin/` | GET / POST | Административная панель |
| `/hr/` | GET | HR-кабинет |
| `/hr/employees/user_id/` | GET | Этапы сотрудника |
| `/modules/<module_id>/` | GET | Учебный материал |
| `/modules/<module_id>/complete/` | POST | Сохранение завершения |
| `/questions/question_id/answer/` | POST | Выполнение |


Учебные обработчики защищены `login_required`. Попытка открыть неопубликованный или несуществующий модуль возвращает 404 для вошедшего пользователя.

## Тестирование

Для проекта подготовлены примеры тестов на основе `django.test.TestCase`:

1. Перенаправление анонимного пользователя с главной на вход.
2. Ответ 404 при открытии скрытого модуля.
3. Сохранение завершения для текущего пользователя без дубликатов.
4. Отображение личного прогресса каждого пользователя.
5. Дополнительный тест: GET-запрос не завершает модуль и возвращает 405 вошедшему пользователю.

**Статус:** наличие всех тестов в локальном файле и успешный результат их запуска нужно подтвердить. В документации не заявляется, что тесты уже прошли.

Запуск:

```powershell
.\.venv\Scripts\python.exe manage.py test onboarding --verbosity 2
```

Или в активном окружении:

```powershell
python manage.py test onboarding --verbosity 2
```

Тесты используют отдельную тестовую базу и не должны изменять рабочие записи в `db.sqlite3`. Сервер разработки для запуска тестов не нужен.



## Этап 3: сохранение ответов, путь 30/60/90, наставник, интерфейс

Что добавлено (нужны миграции `python manage.py migrate`). Страница самочувствия сюда не входит: пункты меню «Самочувствие» появляются автоматически, как только в `health/urls.py` раскомментированы маршруты `health_form` и `hr_health`.

- **Сохранение ответов** (`onboarding.AnswerSubmission`): последний ответ сотрудника на вопрос модуля и число попыток. Если у вопроса все варианты помечены верными (вопросы о ценностях), правильного ответа нет: сотрудник видит нейтральное сообщение, а в `is_correct` хранится пусто. HR-страница `/hr/answers/` показывает только распределение ответов, без имён.
- **Путь 30/60/90** (приложение `journey`): шаги редактируются в админке (`PathStep`), сотрудник отмечает выполнение на `/path/`, HR видит долю выполнивших на `/hr/path/`. Команда `python manage.py seed_path_steps` создаёт ПРИМЕРНЫЕ шаги с пометкой «пример»; содержание должны утвердить компания и руководитель.
- **Спросить наставника**: сотрудник задаёт вопрос на `/mentor/`, HR отвечает на `/hr/mentor/`. Отдельной роли «наставник» нет: отвечает пользователь из группы HR.
- **Интерфейс**: нижняя навигация на экранах до 900 px, пустые состояния, страницы 403/404/500, ссылка «Перейти к содержимому», `aria-current`, режим «Аа» (крупный шрифт, хранится в браузере), защита кнопок от двойной отправки.

Ограничения: логика шагов пути и ответов наставника не проходила проверку на реальных пользователях; режим «Аа» увеличивает размер шрифта на 25% через `rem` (работает во всех браузерах); отступы и размеры блоков в пикселях не меняются.

### Бесшовные переходы

Переходы по меню и отправка форм идут через [Turbo Drive](https://turbo.hotwired.dev/) (файл `onboarding/static/onboarding/js/turbo.js`, версия 8.0.23, лицензия MIT): страница не перезагружается целиком, логотип и анимация не перезапускаются, при смене страницы идёт мягкое затухание (в браузерах с поддержкой View Transitions). Вход, выход, Django-админка, вопросы с проверкой ответа и страницы ошибок открываются обычной загрузкой (`data-turbo="false"` в шаблонах и обработчик в `app.js`). Кэш страниц Turbo отключён (`turbo-cache-control: no-cache`), чтобы кнопка «назад» не показывала устаревшие данные. Если подключаете новые скрипты к страницам, инициализируйте их по событию `turbo:load`, а не `DOMContentLoaded`.
